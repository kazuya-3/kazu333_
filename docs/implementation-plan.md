# KAZU WORKS 実装計画書

作成日: 2026-07-28 / 対象: MVP 初期リリース

## 1. 目的

本業がシステムエンジニアである個人が、平日夜間・土日を中心に小規模案件を受けるための
**オンライン事務所 + ポートフォリオ + 簡易ショップ** を 1 サイトに統合する。

訪問者が取れる行動を 4 本の導線に整理し、どのページからでも次の一歩を選べるようにする。

| 導線 | 目的 | 到達先 |
| --- | --- | --- |
| 見る | 何を頼めるか理解する | `/`（対応できること）・`/works` |
| 測る | 費用感を自分で掴む | `/estimate` |
| 話す | 相談する | `/contact` |
| 買う | 完成品をそのまま買う | `/shop` |

補助導線として「応援チップ」をフッター手前に控えめに置く。

## 2. 技術構成の判断

**採用: Astro 5 + Preact islands + 素の CSS（デザイントークン）**

| 観点 | 判断 |
| --- | --- |
| 出力 | 全ページ静的生成（`output: 'static'`）。CDN 配信だけで動く |
| JS 量 | 既定 0KB。見積もりウィザードと問い合わせフォームのみ island 化 |
| UI ライブラリ | Preact（React 互換 API・約 4KB gzip）。React を使うより島 1 つあたり ~40KB 軽い |
| CSS | Astro のスコープ付き `<style>` + CSS 変数。Tailwind 等は入れない |
| アニメーション | CSS + `IntersectionObserver` 約 60 行。GSAP/Framer Motion は入れない |
| 依存 | `astro` / `@astrojs/preact` / `@astrojs/sitemap` / `preact` のみ |

Next.js を採らない理由: 本サイトはサーバーランタイムを必要とせず、
Astro の方が既定の JS 出力が小さく、静的 LP + 部分的インタラクションという性質に合うため。

## 3. サイトマップ

```
/                     トップ（12 セクション）
/works                実績一覧（カテゴリ絞り込み）
/works/[slug]         実績詳細（課題 → 対応 → 結果）
/shop                 商品一覧（カテゴリ絞り込み）
/shop/[slug]          商品詳細（内容物・利用範囲・購入導線）
/estimate             簡易見積もり（4 ステップ）
/contact              問い合わせフォーム
/privacy              プライバシーポリシー（テンプレート）
/terms                利用規約（テンプレート）
/legal/tokushoho      特定商取引法に基づく表記（テンプレート）
/404                  Not Found
/sitemap-index.xml    自動生成
/robots.txt           静的
```

トップページのセクション順:
ヘッダー → ファーストビュー → よくある相談 → 対応できること → 実績 →
見積もり案内 → ショップ → 依頼の流れ → 自己紹介 → FAQ → 問い合わせ CTA → 応援チップ → フッター

## 4. 情報設計の方針

- **技術名ではなく困りごとで入口を作る。** 「よくある相談」を「対応できること」より前に置く。
- **密度に緩急をつける。** ファーストビュー / 見積もり案内 / 問い合わせ CTA は余白を大胆に取り、
  実績・ショップ・FAQ は情報密度を上げる。
- **Bento 的グリッドを使うが形は揃えない。** 「対応できること」は 3 カラムの縦長カード、
  「よくある相談」はチップ状、「実績」は 2:1 の混在グリッド。
- 1 セクション 1 メッセージ。見出しは日本語、ラベルは英語という二層構造で最新感を出す。

## 5. データモデル

すべて `src/config/` 配下の TypeScript ファイルで管理する（型付き・IDE 補完が効く）。
本文を書き換えるだけでサイトが更新でき、複数ファイルを探し回らない構成にする。

| ファイル | 管理する内容 |
| --- | --- |
| `site.ts` | サイト名・運営者・キャッチコピー・対応時間・連絡先・SNS・SEO 既定値 |
| `services.ts` | よくある相談 / 対応できること 3 カテゴリ |
| `works.ts` | 実績（課題・対応・結果・使用技術・ギャラリー・公開可否・featured） |
| `products.ts` | 商品（価格・内容物・利用範囲・購入 URL・status・featured） |
| `pricing.ts` | 見積もりの分野・依頼内容・規模・追加条件・金額ルール・税表示 |
| `faq.ts` | FAQ |
| `flow.ts` | 依頼の流れ / 安心材料 |
| `about.ts` | 自己紹介・スキル・使用ツール・対応時間 |
| `support.ts` | 応援チップ（金額候補・外部リンク） |
| `legal.ts` | 法的表記のプレースホルダ（住所・氏名等は未入力と分かる形） |
| `contact.ts` | 問い合わせフォームの選択肢・送信方式設定 |

`works` / `products` は配列に 1 要素追加するだけで一覧・詳細・sitemap に反映される。

### 実績データ（要点）

```ts
{ slug, title, category, summary, thumbnail, challenge, solution, result[],
  tech[], duration, gallery[], links[], visibility: 'public'|'limited'|'private',
  featured, publishedAt }
```

`visibility: 'private'` の実績はビルド出力に含めない（詳細ページも生成しない）。

### 商品データ（要点）

```ts
{ slug, name, catch, description, price, salePrice?, preview, gallery[],
  contents[], formats[], environment, license{ commercial, modify, redistribute, credit },
  updatedAt, purchaseUrl?, status: 'onSale'|'preparing'|'soldOut', category, featured }
```

`purchaseUrl` が未設定なら購入ボタンは出さず、status に応じて
「準備中 / 販売開始をお知らせ」「この商品について問い合わせる」を表示する。壊れたリンクを出さない。

## 6. 見積もりロジック

計算は `src/lib/estimate.ts` の純関数 1 つ、料率は `src/config/pricing.ts` の 1 か所に集約する。
条件分岐をコンポーネントへ散らさない。

```
1. 依頼内容 task を選ぶ → 基準レンジ base[min,max] と基準日数 days[min,max] を得る
   （分野だけ選んで内容が「分からない」場合は分野の既定レンジを使う）
2. 規模係数を掛ける      scale: small 0.7 / standard 1.0 / multi 1.8 / unknown 1.0(幅を広げる)
3. 数量係数を掛ける      1 + (qty - 1) * 0.6   ※逓減させ、点数比例で高騰させない
4. 追加条件の加算率を合計 rush +0.3 / 複数案 +0.2 / 複数ファイル +0.25 /
                          元データ納品 +0.15 / 仕様整理 +0.2 / 元データなし +0.1 /
                          修正回数追加 +0.1
5. min/max それぞれへ適用し、下限は最低受注額 3,000 円で丸める
6. 500 円単位へ丸め、上限が要見積もりしきい値（80,000 円）を超えたら
   金額を出さず「要見積もり」を返す
7. 納期は base days に規模・数量を反映し、短納期指定があれば圧縮して下限を 2 日で止める
```

出力は「概算レンジ・想定納期・想定内容の要約・注記」。単一金額は出さない。
税表示は `pricing.tax = { mode: 'included', label: '税込' }` で一元管理する。

結果は `sessionStorage` に保存し、`/contact?from=estimate` で自動的に引き継ぐ。

## 7. デザイントークン

`src/styles/tokens.css` に CSS 変数として定義。詳細は `docs/design-tokens.md`。

- ベース: 温かいオフホワイト `#FBFAF8` / ミルキーホワイト `#FFFFFF` / 薄グレー `#F1F2F5`
- メイン: アイスブルー `#5AA9E6` / ラベンダー `#A9A0F0` / ミント `#6FD6C4`
- アクセント: コーラル `#FF8A80` / ビビッドブルー `#2F7DE1` / シトラス `#FFD166`（少量）
- 文字: `#1D2430`（本文）/ `#5A6478`（補助）— オフホワイト上でコントラスト比 4.5:1 以上
- 角丸 4 段階 / 影 3 段階（すべて青みを含む柔らかい影）/ 余白 8px グリッド

背景には薄いメッシュグラデーション + 粒子を敷き、セクション境界を曲線でつなぐ。

## 8. アクセシビリティ方針

- `prefers-reduced-motion: reduce` で出現・浮遊・視差をすべて停止（`@media` 一括）
- 見出しは h1 → h2 → h3 の順序を崩さない。ページごとに h1 は 1 つ
- 見積もりウィザードは `role="group"` + `aria-current="step"`、
  結果は `role="status"` で読み上げる。キーボードのみで完了できる
- フォームは `<label>` 紐付け、エラーは `aria-describedby` + `aria-invalid`、
  文言は利用者を責めない表現に統一
- 状態を色だけで表さない（バッジは色 + テキスト）
- タップ領域は最小 44×44px

## 9. 実装順序

1. Phase 1: 設計ドキュメント（本書 / サイト構成 / デザイントークン）
2. Phase 2: Astro 設定・トークン・レイアウト・ヘッダー / フッター・データファイル
3. Phase 3: トップ・実績・ショップ・見積もり・問い合わせ・法的ページ・404
4. Phase 4: 見積もりウィザード / フォーム island、スクロール演出、モバイル固定 CTA
5. Phase 5: `astro check` / `astro build` / リンク・レスポンシブ・a11y 確認
6. Phase 6: README・`.env.example`・デプロイ手順・拡張候補

## 10. MVP に含めないもの

ログイン / 会員登録 / 独自カート / 在庫管理 / レビュー / クーポン / 独自決済基盤 /
管理画面 / CMS / 通知システム。いずれも後から足せるよう、
決済は外部リンク、問い合わせ送信はアダプター差し替えで拡張できる形にしておく。
